# 4. Explain the Different Types of Security Policies

## Introduction

A **security policy** is a set of rules and guidelines used by an organization to protect its **information, systems and resources** from misuse, destruction and unauthorized access. Security policies provide the foundation for an organization's security architecture. 

The major types of security policies are:

---

## 1. Enterprise Information Security Policy (EISP)

EISP is a **high-level policy** that defines the organization's overall direction and approach to information security. It establishes the scope and responsibilities of the security program. 

It generally covers:

* Security objectives and philosophy
* Roles and responsibilities
* User responsibilities
* Legal and compliance requirements
* Penalties for violations

---

## 2. Issue-Specific Security Policy (ISSP)

ISSP provides **specific guidelines for a particular technology or security issue**. It may need regular updates as technology and threats change. 

Examples include policies for:

* E-mail usage
* Internet and web usage
* Antivirus protection
* Hacking
* BYOD
* Portable storage devices
* Cloud storage

---

## 3. Systems-Specific Security Policy (SysSP)

SysSP provides detailed rules for the **implementation, configuration and management of a particular system or technology**. It may contain both managerial guidance and technical specifications. 

Technical specifications can include:

* Configuration rules
* System policies
* Access-control requirements
* Technology management procedures

---

# 4. Confidentiality Policies

A **confidentiality policy** protects secret and sensitive information from **unauthorized disclosure**. It ensures that only authorized users can access information. 

### Bell–LaPadula (BLP) Model

The PDF uses **Bell–LaPadula** as a model for confidentiality. It uses multiple security levels such as:

* **Top Secret (TS)**
* **Secret (S)**
* **Confidential (C)**
* **Unclassified (UC)**

Users can access information according to their appropriate security clearance. 

---

# 5. Integrity Policies

An **integrity policy** protects the **accuracy, quality and trustworthiness of data** rather than keeping the data secret. It mainly prevents improper modification of information. 

### Important Models

**Low Water Mark:**
The trustworthiness of information can decrease when less trustworthy information is introduced into the system. 

**Biba's Model:**
Biba's model protects the **integrity and trustworthiness of data** and can be viewed as an approach complementary to Bell–LaPadula's confidentiality model. 

### Principles of Integrity

1. **Separation of Function** – Different functions that do not need the same resources should not share them.
2. **Separation of Duty** – Critical tasks should be performed by at least two different people.
3. **Auditing** – Auditing helps identify integrity failures and supports recovery. 

---

# 6. Hybrid Security Policies

A **Hybrid Security Policy** combines two or more access-control models to provide both **strong security and flexibility**. It can combine:

* **MAC** – Mandatory Access Control
* **DAC** – Discretionary Access Control
* **RBAC** – Role-Based Access Control
* **ABAC** – Attribute-Based Access Control 

### Components

* **MAC:** Uses system-wide rules and security classifications.
* **DAC:** Resource owners can grant or revoke permissions.
* **RBAC:** Access is assigned according to user roles.
* **ABAC:** Access decisions are based on attributes such as user, resource, device, time or location. 

### Example

A user may access financial data only when:

1. The user has the **Finance Officer** role.
2. The user has the required security clearance.
3. The user uses an approved device.
4. The file owner has granted permission. 

### Advantages

* Greater flexibility
* Better security enforcement
* Fine-grained access control
* Context-aware access
* Suitable for cloud and enterprise environments
* Easier management in large organizations 

### Limitations

* Increased complexity
* Possible conflicts between policies
* Requires skilled administration 

---

## Conclusion

Security policies provide a structured approach to protecting organizational information. **EISP** provides overall security direction, **ISSP** addresses specific issues, and **SysSP** provides system-level rules. **Confidentiality policies** prevent unauthorized disclosure, **integrity policies** protect data accuracy and trustworthiness, and **hybrid policies** combine different access-control models to provide flexible and strong security.
