# Connecting a Web Application to AWS IoT Using MQTT

**Introduction:** AWS IoT Core enables secure communication between IoT devices, web applications and AWS services using lightweight protocols like **MQTT (Message Queuing Telemetry Transport)**. MQTT is ideal for low-bandwidth, high-latency networks. A web application can connect to AWS IoT Core to publish messages to topics and subscribe to receive messages in real time.

---

## 1. MQTT Basics
- **Lightweight publish/subscribe protocol** designed for constrained devices and unreliable networks.
- **Publisher:** sends messages to a topic.
- **Subscriber:** receives messages from the topics it subscribes to.
- **Message broker:** AWS IoT Core's broker routes messages between publishers and subscribers.
- **MQTT over WSS (WebSockets Secure):** used by browser-based web applications to connect securely to the broker.
- AWS IoT Core also supports HTTPS (publish only) and LoRaWAN.

## 2. Architecture
**Web application (MQTT client) ⇄ MQTT over WSS ⇄ AWS IoT Core message broker ⇄ IoT devices / AWS services (Lambda, S3, DynamoDB)**

## 3. Steps to Connect a Web Application

### Step 1: Create an AWS IoT Thing
- Go to **AWS IoT Core Console → Manage → Things → Create Thing**.
- Give it a name (e.g., `webClientThing`).
- Download the **certificates and private key** generated by AWS IoT.

### Step 2: Attach a Policy
- Create an **IoT Policy** that allows the actions `iot:Connect`, `iot:Publish`, `iot:Subscribe` and `iot:Receive`.
- Attach the policy to the certificate.

**Example policy:**
```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["iot:Connect", "iot:Publish", "iot:Subscribe", "iot:Receive"],
    "Resource": ["*"]
  }]
}
```

| Action | Purpose |
|---|---|
| iot:Connect | Allows the client to connect to the broker |
| iot:Publish | Allows publishing messages to topics |
| iot:Subscribe | Allows subscribing to topic filters |
| iot:Receive | Allows receiving messages from subscribed topics |

### Step 3: Configure an MQTT Client in the Web App
Use the **AWS IoT Device SDK for JavaScript** or the **Paho MQTT Client** in the web app.

**Example using AWS IoT Device SDK (Browser):**
```javascript
const AWS = require('aws-sdk');
const AWSIoTData = require('aws-iot-device-sdk');

const device = AWSIoTData.device({
  region: 'us-east-1',
  host: 'YOUR_ENDPOINT.amazonaws.com',
  clientId: 'webAppClient',
  protocol: 'wss',               // Secure WebSocket
  maximumReconnectTimeMs: 8000,
  accessKeyId: 'YOUR_ACCESS_KEY',
  secretKey: 'YOUR_SECRET_KEY',
  sessionToken: 'YOUR_SESSION_TOKEN'
});

device.on('connect', () => {
  console.log('Connected to AWS IoT!');
  device.subscribe('iot/webapp/topic');
  device.publish('iot/webapp/topic',
    JSON.stringify({ message: 'Hello from Web App!' }));
});
```

**Explanation of the code:**
- `region` and `host`: the AWS region and your account's IoT endpoint.
- `clientId`: unique identifier of the client.
- `protocol: 'wss'`: secure WebSocket connection.
- `maximumReconnectTimeMs`: maximum time between reconnection attempts.
- `accessKeyId`, `secretKey`, `sessionToken`: temporary credentials used to authenticate.
- `device.on('connect')`: runs once the connection is established.
- `device.subscribe()`: subscribes to the topic `iot/webapp/topic`.
- `device.publish()`: publishes a JSON message to the topic.

### Step 4: Test with the AWS IoT MQTT Test Client
- Go to **AWS Console → AWS IoT Core → MQTT Test Client**.
- **Subscribe** to your topic (`iot/webapp/topic`).
- Messages sent from the web app appear **in real time**.

## 4. Security Considerations
| Concern | Mitigation |
|---|---|
| Data confidentiality | TLS encryption (MQTT over WSS), IAM roles, KMS |
| Authentication and authorization | X.509 certificates, IAM policies, Cognito Identity Pools for user-based access |
| Device identity spoofing | Unique certificate per device, mutual TLS |
| Denial of Service | Rate limiting, AWS WAF, IoT Device Defender |

**Good practice:** Do not hard-code access keys in browser code. Use temporary credentials (for example through Cognito Identity Pools) and restrict the policy to specific topics instead of `"Resource": ["*"]`.

## 5. Example Flow
Web app publishes to `iot/webapp/topic` → **AWS IoT Core** → **Lambda** (processing) → **S3 / DynamoDB** (storage) → dashboard or alert.

---

## Conclusion
Connecting a web application to AWS IoT involves creating a Thing, attaching a policy that permits the MQTT actions, configuring an MQTT client over secure WebSockets, and verifying the messages with the MQTT Test Client. This lets web applications exchange data with IoT devices and AWS services securely and in real time.
